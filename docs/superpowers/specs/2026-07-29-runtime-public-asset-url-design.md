# Runtime Public Asset URL Design

## Goal

Every graph and downloadable artifact returned by the agent must use the URL through which the API request is currently reached, so an expired quick Cloudflare tunnel cannot make a successfully generated graph invisible.

## Context

`tools.public_url` currently derives every `/graphs/` and `/downloads/` URL from the process-wide `SERVE_BASE_URL`. A quick Cloudflare tunnel changes hostname whenever it restarts, while the container environment keeps the earlier value. The graph file remains present and the local `/graphs/` endpoint returns HTTP 200, but Open WebUI receives a stale public hostname.

## Chosen design

The FastAPI request establishes a request-scoped public origin for the duration of one chat-completion response. URL construction resolves in this order:

1. an explicit, non-local `SERVE_BASE_URL`, for a deliberately configured stable public domain;
2. `X-Forwarded-Proto` plus `X-Forwarded-Host`, when the reverse proxy provides them;
3. the request scheme and `Host` header;
4. the existing local default (`http://localhost:8000`) outside a request context, including CLI and isolated tool tests.

The resolved origin is stored with `contextvars.ContextVar`, so concurrent requests cannot leak an origin into one another. It is entered at the FastAPI request boundary and reset after both streaming and non-streaming responses finish. Existing `graph_url()` and `download_url()` callers remain unchanged.

## Proxy contract

The Open WebUI-to-agent connection must forward `X-Forwarded-Host` and `X-Forwarded-Proto` from the browser-facing proxy. The server validates only syntactically safe forwarded host values (no whitespace, path, or user-info) before using them. If the headers are absent, the direct request host remains valid for direct API use.

## Error handling

If forwarded headers are malformed or missing, URL construction does not fail and falls back to the next source. The server never reuses an origin from a previous request.

## Verification

- A request with Cloudflare-style forwarded headers produces graph and download links under that exact public origin.
- A second request with a different origin produces only the second origin, proving context isolation.
- A request without proxy headers uses its request host.
- The current no-request behavior remains local for CLI/tool callers.
- A FastAPI integration test confirms the response body generated by `run_graph` contains the request-scoped graph URL.
